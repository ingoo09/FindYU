# 권기백 · 백엔드 및 DB · Claude Code

[공통 구현 명세](00_공통.md), `CLAUDE.md`, `docs/API.md`를 읽는다. 5시간 내 목표는 SQLite와 기존 라우트를 재사용해 **등록 분석과 검색 비교를 FactChat Gateway의 Gemini에 연결**하는 것이다. AI 소유 경로 외 `backend/`와 `docs/API.md`를 맡는다.

## B1. 이미 있는 계약 재사용

- `GET /form-schema`, `POST /items/analyze`, `POST /items`, `POST /search`, `GET /items`, 장소·상세 라우트를 유지한다. 장소·품목 필터, 최신순 페이지네이션, 이미지 URL은 현재 API를 그대로 활용한다.
- 등록 `image`와 반복 `extra_images`는 기존 1~5장 입력·기존 데이터와 호환한다. 프론트의 신규 등록 최소치는 2장이다. 같은 사진 묶음에 유효한 `analysis_id`가 있으면 재사용하고, 사람이 수정한 체크 폼 값을 저장한다. 사람과 AI의 품목이 다르면 기종·브랜드와 이전 품목 전용 AI 값을 버린다.
- 분석을 사용할 수 없을 때 프론트가 `defer_analysis=true`로 직접 입력을 제출하면 AI 호출을 시작하지 않고 `registered` 상태와 `id`를 반환한다. 유효한 `analysis_id`가 함께 있으면 재사용 가능하다. 사진·입력값은 기존 DB·파일 경로에 저장한다. 새 상태, 마이그레이션, 재처리 큐를 추가할 필요가 없다.

## B2. Gemini 검색 라우트 한 경로

1. 기존 `category`·`filters`를 검증하고 `found` 후보를 조회한다. `registered`인 정상·수동 등록은 모두 검색 대상이다. 현재 체크 폼의 `일치`·`미확인` 규칙과 `total_candidates` 의미를 유지한다.
2. 공통 규격에 따라 최대 10건을 고른다. 사진 검색에서 읽을 수 없는 대표 사진을 제외한다. 설명 검색에서 사진이 없으면 저장된 외형·폼 값을 쓸 수 있다. DB ID와 비교 자료만 AI 담당의 검색 어댑터에 보낸다. 브라우저·파일 경로, DB 원본과 사용자의 개인 정보는 모델 입력으로 제공하지 않는다.
3. 모델이 반환한 후보 ID가 요청에 포함된 고유 ID인지 검사한다. 결과 순서를 유지해 실제 DB 레코드와 기존 `filter_check`를 붙이고 `match_reasons`, `evaluated_count`를 포함한다. 결과는 앱이 지정한 Top-5 이내다. 후보가 없으면 200과 빈 결과를 돌려준다. Gateway 연결 실패·잘못된 모델 출력은 현재 오류 응답 규격의 502/503 계열로 보내고, 실제 조회 성공 0건과 구분한다.
4. 구동과 등록·검색에 기존 로컬 모델의 로딩·임베딩·백필 호출이 필요 없게 연결한다. 기존 DB의 과거 임베딩 컬럼은 보존할 수 있다. 응답의 구형 점수 필드는 새로운 값으로 채우지 않는다. 제거 또는 전환용 `null` 규격은 프론트와 합의해 `docs/API.md`에 적는다.
5. 기존 `FINDYU_BAZE_MODEL`로 두 모델을 전환하고, 목표 `FINDYU_SEARCH_ANALYZER_MODE=mock|baze`로 테스트와 운영을 구분한다. 테스트는 모의 게이트웨이를 사용한다. AI 파일 변경은 최준서와 맞춘다.

## 최소 검증

`backend/`에서 `.venv/bin/python -m pytest tests`를 실행한다. 등록 후 실제 `id`가 상세·목록에서 일치, 수동 등록 공급자 호출 0회, 사진·자연어 검색에서 올바른 ID와 근거, 0건·중복/외부 ID·Gateway 장애 처리, 로컬 모델 없이 시작되는지 확인한다. 결과 계약은 변경과 같은 커밋에서 `docs/API.md`에 넣고 프론트·PM에 전달한다.
