# 김승보 · 프론트엔드 및 UI/UX · Codex

[공통 구현 명세](00_공통.md)를 읽는다. `frontend/src/App.jsx`의 기존 등록·검색·후보 컴포넌트를 유지하면서 필수 로직만 바꾼다. Dashboard 내부 구현은 이수형 담당이다.

## F1. 등록

- 기존 품목·체크 폼을 쓴다. 세 품목을 선택하면 해당 촬영 가이드를 보여준다. 유효한 기본 사진 2장이 있어야 분석·등록할 수 있고 보완 사진은 최대 3장이다. 기존 미리보기와 대표 기능을 재사용한다. 새로운 촬영 위저드나 이미지 편집기를 만들 필요는 없다.
- 사진 묶음이 바뀌면 예전 분석 결과를 보내지 않는다. 같은 묶음의 `analysis_id`를 등록에 쓰고, `needs_check`와 `photo_hint`를 기존 폼에 표시한다. 직접 수정한 값은 유지하고, 품목이 바뀌면 이전 품목 전용 값을 비운다.
- 분석 실패 시 에러를 표시하고 직접 입력해 등록할 수 있다. 사용자가 수동 경로를 선택한 경우 `defer_analysis=true`를 보내고 분석 재호출을 하지 않는다. 중복 제출을 막고 실패 시 사진과 입력을 유지한다. 실제 `id`를 받은 뒤 성공을 표시한다.

## F2. 검색과 홈

- 기존 사진·자연어 입력과 체크 폼을 사용한다. 사진만 또는 설명만 넣고 `top_k=5`를 보내는 흐름을 각각 확인한다. `results[]` 순으로 후보 카드를 렌더링한다. 기존 백분율·수치 게이지를 제거하고 순위, `match_reasons`, `filter_check`, 사진·외형·장소·습득 시각을 보여준다. `evaluated_count`가 `total_candidates`보다 적으면 비교에 사용한 건수를 보여준다. 누락 필드는 안전하게 생략한다.
- 기존 후보 상세를 재사용한다. 검색 성공 0건, API 요청 중, 일시 오류를 구분한다. 브라우저는 FindYU API만 호출하며 모델 선택은 서버 설정을 사용한다.
- 홈의 **분실물 찾기**와 **습득물 등록** 아래에 Dashboard를 연결한다. 프론트가 `App.jsx`에서 다음 연결을 맡는다. Dashboard 모듈 병합 후 연결한다.

```jsx
import FoundItemsDashboard from "./dashboard/FoundItemsDashboard";

<FoundItemsDashboard apiUrl={apiUrl} assetUrl={assetUrl} />
```

## 최소 검증

`frontend/`에서 `npm run build`를 실행한다. 통합 브라우저에서 등록 1장 차단·2장 성공·최대 5장, 분석 실패 뒤 수동 저장, 사진·설명 각각 후보 검색, 홈에서 목록 재조회로 E2E-01~04를 확인한다.
