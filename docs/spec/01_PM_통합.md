# 최인구 · PM 및 시스템 통합 · Codex

[공통 구현 명세](00_공통.md)를 기준으로 5시간 안에 한 커밋에서 등록·검색·Dashboard를 시연할 수 있게 통합한다. 담당 문서·`README.md`·`demo/`를 맡고 기능 코드 변경은 소유자에게 전달한다.

| 시간 | 할 일과 완료 기준 |
|---|---|
| 시작 후 20분 | 최신 `main`과 파일 소유자 확인, 시작 SHA 공유, FactChat 계정의 Flash·Argon 접근 확인, `match_reasons`·`evaluated_count`와 Dashboard 연결 계약 공유 |
| 2시간 | AI가 모델 어댑터와 응답 예시를, 백엔드가 `/search`·수동 등록을 인수할 수 있는 상태인지 확인. 프론트·Dashboard는 mock으로 독립 작업 |
| 3시간 30분 | AI 어댑터 → 백엔드·API 문서 → 등록·검색 UI 순으로 병합. Dashboard 모듈 → 홈 연결 순으로 병합. 사전 등록 물품으로 세 흐름 1회 확인 |
| 4시간 | 기능 동결. Flash의 통합 결과와 Argon 계정 호출 확인. 해결이 덜 된 문제는 5시간 시연을 막는 항목 위주로 처리 |
| 5시간 | 같은 커밋으로 최종 리허설. 작동 버전, 실행 명령, 모델 ID, 시연 데이터와 실패 시 사용할 녹화 보관 |

## 시연 준비

- 허락받은 사진으로 3개 품목을 미리 등록한다. 품목·장소가 겹치는 후보를 포함해 Dashboard 필터를 시연할 수 있게 한다. 등록 사진과 검색 사진은 가능한 한 다른 각도를 쓰고 정답 ID는 따로 기록한다.
- 시연은 홈 → 등록 사진 2장 → AI 초안 확인·수정 → 목록과 상세 확인 → 사진 또는 자연어 검색 → 후보 확인 순서다. 나머지 검색 경로도 리허설에서 실행한다.
- Flash로 통합 규격을 확인하고 Argon으로 실사용 목표를 검증한다. 두 모델의 모드·응답 시간·성공 여부를 구분해 기록한다. Argon 접근 실패를 Flash 결과로 대체해 실사용 성공으로 보고하지 않는다.
- Gateway 장애 시 Dashboard와 수동 등록을 열고, 검색 비교는 같은 데이터로 미리 녹화한 화면을 사용한다. 재현할 수 있는 결과만 발표하고 팀원 역할·AI 호출 방식·실측 수치를 맞춘다.
- 완료 체크는 공통 E2E-01~05로 관리한다. 팀 공통 에이전트 규칙의 예전 모델·필수 작업 표기는 담당 PM 문서에서 최신 명세와 맞춘다.
