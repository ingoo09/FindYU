# FindYU 해커톤 공통 시작 프롬프트

Codex 또는 Claude Code에서 FindYU 저장소를 열고 **아래 코드 블록 하나를 복사한다. `{}`로 감싼 세 값을 직접 바꾼 뒤 중괄호를 지우고, 아래의 파일 4개를 한 메시지에 첨부해 보낸다.** 역할별 문서에 적힌 작업 번호와 파일 범위는 에이전트가 읽는다.

| 바꿀 부분 | 넣을 값 |
|---|---|
| `{이름}` | 본인 이름. 예 `최준서` |
| `{역할}` | 아래 역할 표의 역할 이름. 예 `AI` |
| `{실호출 준비 상태}` | `설정됨`, `미설정`, `해당 없음` 중 하나. 예 `설정됨` |

## 복사할 프롬프트

```text
나는 FindYU 팀의 {이름}이고, 내 담당 역할은 {역할}이다.
FactChat 실호출 준비 상태는 {실호출 준비 상태}이다.
첨부한 문서를 바탕으로 내 역할의 해커톤 구현을 시작해줘.

1. 첨부한 구현명세 폴더의 README.md 변경표, 00_공통.md, 내 역할 명세, 5시간 실행 계획을 읽어줘. 사진 임베딩과 검색 모드는 첨부 README의 변경표를 적용하고, 요청·응답은 열린 저장소의 최신 docs/API.md를 기준으로 해줘. 저장소의 AGENTS.md를 읽고, Claude Code라면 CLAUDE.md도 확인해줘.
2. 현재 작업 브랜치와 기준 커밋을 확인해줘. 기존 변경을 보존하고, 저장소 규칙에 따라 최신 main 기준의 역할별 작업 브랜치에서 진행해줘. 이미 병합된 기능은 재사용하고, 첨부한 역할 명세와 실행 계획에서 내 작업 번호와 수정 범위를 찾아줘.
3. 담당 작업 중 지금 시작할 수 있는 첫 항목을 구현하고 그 항목의 테스트를 실행해줘. 다른 역할의 변경이 필요하면 변경 요청과 이유를 기록해줘. 선행 PR이나 실호출 환경이 준비되지 않았으면, 가능한 작업을 mock으로 진행해줘. 5시간 계획에서 정한 통합 순서와 기능 동결 시점을 지켜줘.
4. 작업을 마치면 변경 파일, 실제 실행한 테스트와 결과, 다른 담당자에게 넘길 사항, 아직 확인하지 못한 항목을 한국어로 정리해줘.
```

## 함께 첨부할 파일 4개

1. [README.md](README.md) — 이 구현명세 폴더의 임베딩 변경표
2. [00_공통.md](00_공통.md) — 공통 구현 명세
3. [2026-11-25-findyu-hackathon.md](plans/2026-11-25-findyu-hackathon.md) — 5시간 실행 계획
4. 아래 표의 **자기 역할 명세 하나**

| 담당자 | `{역할}`에 넣을 값 | 도구 | 첨부할 역할 명세 |
|---|---|---|---|
| 최인구 | `PM·통합` | Codex | [01_PM_통합.md](01_PM_통합.md) |
| 최준서 | `AI` | Codex | [02_AI.md](02_AI.md) |
| 권기백 | `백엔드·DB` | Claude Code | [03_백엔드_DB.md](03_백엔드_DB.md) |

| 이수형 | `Dashboard` | Codex | [05_Dashboard.md](05_Dashboard.md) |

첨부 README는 저장소 루트의 README와 다른 파일이다. [팀원 준비·전달 체크리스트](plans/2026-11-25-findyu-team-inputs.md)는 첨부 전에 본인이 확인한다. FactChat 키가 필요한 담당자는 값을 `backend/.env`에 직접 설정하고, 프롬프트에는 설정 상태만 적는다. 프론트엔드와 Dashboard 담당자는 `해당 없음`으로 적는다.
