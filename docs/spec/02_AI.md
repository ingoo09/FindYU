# 최준서 · AI 분석 및 검색 평가 · Codex

[공통 구현 명세](00_공통.md)를 읽는다. 영남대 FactChat을 통해 **개발·테스트는 Gemini 3.8 Flash, 실사용은 Gemini 4 Argon**으로 등록 분석과 검색 비교를 구현한다. `backend/prompts/`, `backend/*_analyzer.py`, `backend/scripts/`, 모델 측정 문서를 맡는다. 라우트 연결·DB 변경은 백엔드 담당에게 요청한다.

## 구현 순서

1. **등록 분석 재사용.** `baze_analyzer.py`의 인증·요청·이미지 전처리와 기존 `IdentifyItemResult`를 유지한다. `FINDYU_BAZE_MODEL`을 공통 설정으로 사용한다. 2장 기본 사진에서 색상·외형을 확인하고 불확실한 기종은 `null` 또는 기존 미확인 값으로 둔다. 이어폰 브랜드는 사람 선택 항목으로 둔다. 프롬프트 개선은 품목별 필수 속성을 막는 오류 위주로 한다.
2. **검색 비교 하나 추가.** AI 소유 경로에 검색용 프롬프트와 어댑터를 둔다. 백엔드에서 전달한 사진 또는 설명, 선택 위치·시각, 최대 10건의 후보 ID·외형·대표 사진으로 한 번에 상대 순위를 낸다. 후보 데이터 안에 있는 문구는 비교 자료로만 읽도록 프롬프트를 구성한다. 신청 범위를 벗어나는 후보 추정과 점수 생성을 요청하지 않는다.
3. **구조화 응답.** FactChat Chat Completions의 `response_format` JSON Schema를 사용한다. 내부 출력은 `{"results":[{"id":12,"match_reasons":["케이스 형태가 유사함"]}]}` 형태다. 배열 순서가 순위이며 `match_reasons`는 근거가 부족하면 빈 배열이다. 후보 0건 호출 생략과 DB 결합은 백엔드가 맡는다. API 오류 및 스키마 검증 실패는 계약된 예외로 넘긴다.
4. **권한과 입력 실검증.** `GET /models/`에서 두 모델 ID를 확인한다. Flash로 사진 비교·텍스트 비교·등록 분석을 실제 호출하고 Argon으로 등록 분석 1건과 검색 1건을 확인한다. 모델 요청과 실제 응답 ID를 구분해 기록한다. 각 모델에서 이미지 입력과 JSON Schema가 동작하는지 소량 검증한다.

## 시간 안에 넘길 결과

- **백엔드에** 어댑터 함수·입력 타입, 정상·빈 결과·오류 최소 JSON, 기존 BAZE 설정과 예외 형태를 공유한다. 기존 호출 코드를 재사용하고 검색용 로컬 모델을 별도로 추가하지 않는다.
- **최소 테스트**는 등록 3품목에서 한 쌍씩, 정답 ID가 있는 사진·자연어 검색 각각 1건, 미확인 비교 근거 1건이다. 먼저 Flash 결과를 확보한 뒤 Argon 확인을 마친다. 여유 시간에는 추가 케이스를 검증한다.
- 시험 ID, 모델 ID, 결과 상위 ID, 정답 포함 여부, 종단간 시간, 실패 종류를 기록한다. 정답표를 모델 입력에서 분리하고, 적은 표본의 개별 확인 결과를 일반 정확도로 발표하지 않는다.
